## Project Overview

argNorm normalizes antibiotic resistance gene (ARG) annotations from various bioinformatics tools to the Antibiotic Resistance Ontology (ARO) maintained by CARD. It maps gene names from different ARG annotation tools/databases to standardized ARO accessions and adds drug categorization columns.

## Commands

### Install and test
```bash
pip install -e '.[dev]'       # editable install with test deps
pytest tests/                 # unit tests (run from repo root)
python integration_tests/run_argnorm.py  # CLI integration tests (compares against golden files in outputs/)
```

### Lint
```bash
flake8 argnorm --select=E9,F63,F7,F82 --show-source --statistics
```

### Run a single test
```bash
pytest tests/test_normalizers.py::test_abricate_normalizer  # parametrized across databases
pytest tests/test_lib.py::test_map_to_aro
```

### CLI usage
```bash
argnorm resfinder -i input.tsv -o output.tsv
argnorm abricate --db ncbi -i input.tsv -o output.tsv
```

## Architecture

### Core pipeline flow
`cli.py` -> `normalize.py` -> `normalizers.py` (tool-specific normalizer classes) -> `lib.py` (mapping table loading + ARO ontology)

1. **`cli.py`**: Parses CLI args, calls `normalize()`, writes output with version comment header via `atomicwrite.py`.
2. **`normalize.py`**: Factory that selects the correct `Normalizer` class based on the `tool` argument.
3. **`normalizers.py`**: Contains `BaseNormalizer` and tool-specific subclasses (`ARGSOAPNormalizer`, `DeepARGNormalizer`, `ResFinderNormalizer`, `AMRFinderPlusNormalizer`, `AbricateNormalizer`, `GrootNormalizer`, `HamronizationNormalizer`). Each overrides methods like `get_input_ids()`, `preprocess_ref_genes()`, and `load_mapping_table()` to handle tool-specific output formats.
4. **`lib.py`**: Loads ARO mapping tables from `argnorm/data/{db}_ARO_mapping.tsv`, merges in manual curations from `argnorm/data/manual_curation/{db}_curation.tsv`, and provides `map_to_aro()` for single-gene lookups and `get_aro_ontology()` for the bundled `aro.obo` file (via pronto).
5. **`drug_categorization.py`**: Traverses the ARO ontology graph to find drugs a gene confers resistance to (`confers_resistance_to()`) and their broader drug classes (`drugs_to_drug_classes()`). Uses `confers_resistance_to_drug_class` and `confers_resistance_to_antibiotic` relationships, walking up superclasses.

### Data files
- `argnorm/data/*.tsv`: ARO mapping tables per database (generated by `db_harmonisation/crude_db_harmonisation.py`, a Jug pipeline).
- `argnorm/data/manual_curation/*.tsv`: Hand-curated overrides that take precedence over RGI-generated mappings. `Cut_Off` is set to `"Manual"` for these entries.
- `argnorm/data/aro.obo`: Bundled ARO ontology file used by pronto.

### Adding support for a new tool/database
1. Create the mapping TSV in `argnorm/data/` and curation TSV in `argnorm/data/manual_curation/`.
2. Add the database name to the `DATABASES` list in `argnorm/__init__.py` (also re-exported as `lib.DATABASES`).
3. Create or update a normalizer class in `normalizers.py` implementing `get_input_ids()` and any necessary `preprocess_ref_genes()`.
4. Register the tool in `normalize.py`'s factory dict and `cli.py`'s argparse choices.
5. Add test data in `examples/raw/` and golden files in `outputs/raw/`.

### db_harmonisation directory
Contains scripts for **building** the mapping databases (not for regular users). Uses [Jug](https://jug.rtfd.io/) for parallelism and [pixi](https://pixi.sh/) for environment management. Run with `pixi run jug execute crude_db_harmonisation.py`.

### Test structure
- `tests/test_normalizers.py`: Tests each normalizer against golden output files in `outputs/`. Tests run from repo root (paths are relative).
- `tests/test_lib.py`: Tests `map_to_aro()` for each database.
- `tests/test_database.py`, `tests/test_arg_category.py`: Database integrity and drug categorization tests.
- `integration_tests/run_argnorm.py`: End-to-end CLI tests comparing output against golden files.

## Key conventions
- pandas is intentionally NOT imported at module level in `__init__.py` and `cli.py` to keep `argnorm -h` fast.
- The `~~~` separator is used as a delimiter in abricate-card gene identifiers to avoid conflicts with other delimiters used by CARD.
- Database name `abricate-card` is normalized to `abricate_card` internally (hyphens to underscores) for file/variable naming.
- CLI output prepends a `# argNorm version: X.Y.Z` comment line; when reading argNorm output, use `skiprows=1`.
- Version is in `argnorm/argnorm_version.py` and read dynamically by setuptools.
